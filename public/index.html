🏃 Runner Slot A (Concurrency: slot-A) STREAMING (00:00 → 04:00)
Runs FFmpeg smooth buffer for 4 hours (14,400s). At 04:00:00, sends GitHub API workflow_dispatch signal to start Slot B, continues streaming for 5 minutes (300s), then stops itself at 04:05:00.
🏃 Runner Slot B (Concurrency: slot-B) STANDBY / WARM OVERLAP READY
Boots immediately when signaled at 04:00:00 (Zero Queue because Slot B has its own concurrency group!). Streams in parallel during the 5-minute overlap, then carries the 24/7 stream for the next 4 hours and signals Slot A back!
✅ Why Zero Queue & Zero Drop?
GitHub Actions hard limit ~6h (configured cap: 5 Hours / 300m). Because each run self-triggers the alternate slot at 4 Hours and exits at 4h 05m, there is always 1 active stream (and 2 during the 5-minute warm handover), never a backlog queue!
